# Git 文件权限噪音污染发布提交

## 现象

发布前 `git status` 出现大量文件变更,但 `git diff --stat` 显示很多文件是 `0` 行变化。

## 原因

文件内容没有变,只是权限位从 `100644` 变为 `100755`。如果直接 `git add .`,会把大量无意义的 chmod 变化提交到 GitHub。

## 解决方案

在当前仓库关闭文件权限位跟踪:

```bash
git config core.filemode false
```

## 预防措施

- 发布前先跑 `git diff --summary`。
- 如果看到大量 `mode change`,先处理权限噪音。
- 不要把这类噪音当作业务改动推送。

## 是否可复用

可复用。Mac 本地项目、跨工具复制文件、AI 工具批量生成文件时都可能出现。
