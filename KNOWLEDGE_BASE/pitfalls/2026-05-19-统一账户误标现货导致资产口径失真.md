# 统一账户误标现货导致资产口径失真

- **日期**: 2026-05-19
- **标签**: #资产口径 #交易所API #合约 #理财

## 现象

资产聚合里原来只有 `spot / earn / futures` 三类来源。OKX、Bybit 这类统一账户会把现货、合约、杠杆、期权保证金混在一个账户余额接口里，原实现容易把统一账户结果标成 `spot`，让用户误以为这是纯现货资产。

## 原因

交易所 API 的账户体系并不统一。现货接口通常清晰，但合约、理财、资金账户、统一账户的字段和权限差异很大。如果只用三分类，会把不同含义的余额压扁，最终造成展示口径失真。

## 解决方案

扩展 `BalanceSource`，新增 `funding / earn_flexible / earn_locked / futures_usdt / futures_coin / futures_usdc / unified / margin / options / unknown` 等细分来源，同时保留旧的 `earn / futures` 作为兼容和失败诊断的大类。

## 预防措施

后续新增交易所或账户类型时，必须先声明资产来源和支持等级，再写接口。不能因为接口名字叫 `getSpotBalance` 就默认结果一定是纯现货。

## 是否可复用

可复用。所有多平台资产聚合项目都会遇到“同名账户不同义”的问题，应优先做清楚资产口径，再追求覆盖数量。
