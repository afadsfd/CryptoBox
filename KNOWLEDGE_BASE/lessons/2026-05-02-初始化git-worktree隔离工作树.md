# 2026-05-02 初始化 Git worktree 隔离工作树

## 本次任务踩的坑

### 坑 1:主工作区存在大量未提交改动
- **现象**: `git status` 显示大量文件处于修改状态。
- **原因**: 当前主目录既包含 App 代码、网页、APK、自动生成文档等改动,直接在这里继续实验容易混在一起。
- **解决方案**: 使用 `git worktree` 在同级目录创建独立工作树 `/Users/zero/Desktop/项目库/资产聚集app-worktree`。
- **预防措施**: 后续大改动优先在独立 worktree 或新分支中完成,稳定后再合并。
- **是否可复用**: 可复用。所有 Git 项目都适用。

## 本次实现的优化

### 优化 1:用 worktree 替代手动复制项目
- **优化前**: 如果需要干净副本,容易手动复制整个项目目录,占空间且容易和 Git 状态脱节。
- **优化后**: 使用 Git 原生 `worktree` 创建独立工作区。
- **收益**: 更省空间,Git 状态清晰,主目录不会被新实验污染。
- **代价**: 需要记住 worktree 和分支的对应关系。
- **是否可复用**: 可复用。适合打包、临时验证、大版本重构。

## 学到的可复用知识

### 知识点 1:同一分支不能同时被两个 worktree 检出
- **场景**: 已经在主目录使用 `main` 分支,还想再创建一个干净副本。
- **要点**: 新 worktree 要使用新分支名,例如 `worktree/main`。
- **示例**:

```bash
git worktree list
git worktree add "/Users/zero/Desktop/项目库/资产聚集app-worktree" -b worktree/main
```
