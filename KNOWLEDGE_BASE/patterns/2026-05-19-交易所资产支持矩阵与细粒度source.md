# 交易所资产支持矩阵与细粒度 Source

- **日期**: 2026-05-19
- **标签**: #资产聚合 #产品口径 #本地优先 #可视化诊断

## 优化前

系统只告诉用户支持某个交易所，资产来源主要压缩成 `spot / earn / futures`。这会让“已支持交易所”和“已完整支持该交易所全部资产”混在一起。

## 优化后

每个交易所都声明自己的资产支持矩阵，包括资产来源、支持等级和备注。页面展示“稳定 / Beta / 部分 / 待补 / 不支持”，首页展示已识别资产类别数和最后同步时间。

## 收益

- 降低误导：用户不会把 Coinbase 的现货支持误解成 futures 也已覆盖。
- 便于排查：同步失败时能按理财、合约等来源提示权限问题。
- 便于迭代：新增交易所时先补能力声明，再逐步实现接口。

## 代价

需要维护一份交易所能力声明表。交易所 API 更新时，要把这张表作为产品口径一起更新。

## 是否可复用

可复用。任何“多供应商 + 不同能力边界”的系统，都适合先做 capability matrix，再做具体适配器。
